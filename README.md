# 데빌 게임즈 (사내 게시판용)

빌드 도구와 서버 없이 정적 파일만으로 돌아가는 웹 게임 모음입니다. 사내 GitHub Pages에 올린 뒤 게시판에 iframe으로 넣어서 씁니다.

| 파일 | 게임 | 솔로 | 멀티 |
|---|---|---|---|
| `index.html` | 게임 목록 | - | - |
| `gradation.html` | 그라데이션 | AI 연습 (쉬움/어려움) | 온라인 1:1 |
| `equation-signal.html` | 수식 신호등 | 오늘의 문제 (모두 같은 문제), 랜덤 연습 | 온라인 1:1 (서로의 비밀 수식 추리) |
| `hit-stay.html` | HIT, STAY | AI 4명과 대결 | 온라인 2~5명 (빈자리는 AI) |
| `hidden-word.html` | 히든 워드 | AI 출제 5문제 (오늘의 문제 / 연습) | 온라인 2~6명 (돌아가며 출제) |
| `data/hw-*.txt, hw-vecs.bin` | 히든 워드 단어 데이터 | | 명사 32,866개 + 256차원 int8 벡터 (8.4MB) |
| `net.js` | 공통 멀티플레이 모듈 | | PeerJS 방 만들기·참가, 생존 신호, 해시 |
| `vendor/peerjs.min.js` | PeerJS 1.5.4 | | CDN 없이 저장소에 포함 |

## 배포 (사내 GitHub Pages)

1. 이 폴더를 사내 GitHub 저장소에 push합니다. (`screenshots/`는 빼도 됩니다.)
2. 저장소의 Settings → Pages에서 `main` 브랜치의 `/ (root)`를 선택합니다.
3. 발급된 주소(예: `https://pages.사내도메인/org/dvplan/`)로 접속해 확인합니다.

로컬에서 확인하려면 `python3 -m http.server 8765`를 실행하고 `http://localhost:8765/`에 접속합니다.

## 게시판에 넣기 (iframe)

```html
<iframe src="https://pages.사내도메인/org/dvplan/hit-stay.html"
        width="100%" height="1000" style="border:0"
        allow="clipboard-write"></iframe>
```

- `allow="clipboard-write"`를 넣어야 iframe 안에서 결과나 링크 복사 버튼이 동작합니다.
- 참가 링크(`?join=코드`)는 게임 페이지를 바로 엽니다. 게시판 글 대신 새 탭에서 열립니다.

## 멀티플레이 구조

- **방 만들기 / 참가**: 방장이 6자리 코드를 받고, 참가자는 그 코드를 입력하거나 참가 링크를 엽니다.
- **연결**: 브라우저끼리 WebRTC로 직접 연결합니다. **처음 연결할 때만** PeerJS 공개 중계 서버(`0.peerjs.com`)를 거치고, 게임 데이터는 플레이어 사이에서만 오갑니다.
- **HIT, STAY**: 방장 브라우저가 게임을 진행합니다. 참가자마다 본인 카드만 보이는 화면 정보를 따로 보내므로, 개발자 도구로 남의 카드를 볼 수 없습니다. 차례마다 60초 제한이 있습니다. 참가자 연결이 10초 이상 끊기면 AI가 그 자리를 이어받습니다.
- **그라데이션 / 수식 신호등 1:1**: 각자 비밀(배치나 수식)을 갖고 시작할 때 `SHA-256(비밀 + 랜덤 salt)` 봉인값만 교환합니다. 경기가 끝나면 비밀을 공개해 봉인값과 그동안의 결과(공개한 숫자, 채점 색)가 맞는지 자동으로 검증합니다.

### 사내망에서 연결이 안 될 때

- 회사 보안 정책상 외부 서버(`0.peerjs.com`, Google STUN)에 접속할 수 없으면 사내에 [PeerServer](https://github.com/peers/peerjs-server)를 하나 띄우고, `net.js` 상단의 `PEER_CONFIG`에 주소를 넣습니다. 모든 게임이 이 설정을 함께 씁니다.
  ```js
  const PEER_CONFIG = { host: 'peer.사내도메인', port: 443, path: '/', secure: true };
  ```
- 방화벽이 WebRTC(UDP)를 막고 있으면 P2P 연결이 실패합니다. 이때는 TURN 서버를 `PEER_CONFIG.config.iceServers`에 추가해야 합니다.
- **HIT, STAY 방장 주의**: 방장이 탭을 닫으면 게임이 끝납니다. 방장 탭이 백그라운드에 있어도 게임은 계속 진행됩니다.

## 히든 워드의 AI 유사도

- 서버나 API 키 없이 동작하도록 **단어 의미 벡터를 미리 계산해 `data/`에 넣었습니다.** 브라우저가 코사인 유사도를 바로 계산하므로 사내망에서도 외부 접속이 필요 없습니다.
- 어휘집
  - 한국어 맞춤법 사전 [hunspell-dict-ko](https://github.com/spellcheck-ko/hunspell-dict-ko) 0.7.94에서 명사만 골랐습니다(32,866개).
  - 정답 후보는 그중 [위키낱말사전 한국어 빈도 5800](https://en.wiktionary.org/wiki/Wiktionary:Frequency_lists/Korean_5800)(국립국어원 자료 기반)에 있는 명사 2,928개입니다.
- 모델
  - `paraphrase-multilingual-MiniLM-L12-v2`와 `LaBSE` 두 모델(모두 Apache-2.0)의 단어 임베딩을 평균해 앙상블했습니다.
  - 평균 제거와 상위 주성분 제거로 허브 현상을 줄였습니다. 허브 현상은 희귀어가 아무 단어와도 비슷하게 나오는 문제입니다.
  - 그다음 PCA로 256차원까지 줄이고 int8로 양자화했습니다.
- 표시값은 코사인 유사도 × 100입니다. 관련 없는 단어는 0% 안팎, 아주 가까운 단어는 60~90%가 나오고, 음수도 나올 수 있습니다.
- 데이터를 다시 만들 때 쓴 스크립트(어휘 추출, 임베딩, 압축)는 저장소에 넣지 않았습니다. 필요하면 요청해 주세요.

## 규칙 출처 및 참고

- 규칙은 「데블스 플랜: 데드 어게인」(시즌 3) 방송 내용을 정리한 공개 자료를 바탕으로 옮겼습니다. 세부 규칙이 방송과 다를 수 있습니다.
- 수식 신호등의 노랑은 "정답에 있는 문자"라는 방송 규칙을 그대로 따랐습니다. 같은 문자가 몇 번 나오는지는 따로 세지 않습니다. 1:1 대결은 10턴이 넘으면 마지막 턴의 초록 개수로 승부를 가립니다.
- HIT, STAY는 매 라운드 덱을 새로 섞습니다.
